# 需求文书骨架（立项期）

立项期需求文书的章级骨架，提炼自先行者立项需求文档的公共形态：What/How 分界、概念立宪、能力分级、粒度到底、排除显式、验收成硬条件。每节括号内是成文判据，写完一节对一次。目标密度：数百行级——需求篇是链内最厚的一篇，厚度来自端点/命令/字段/指标的穷举，不来自论证重复；发现同一段论证出现两次，删。

```md
# {项目名}需求文档

> 引言块：本文定义功能需求与非功能需求，作为技术方案、研发实施、测试验收的依据。
> 回答 What，不回答 How。前置阅读：第一篇调研、第二篇定位——不重复论证领域现状。
（判据：读者看完引言块就知道该先读什么、本文不管什么。）

## 1. 项目概述
### 1.1 {项目名}是什么
一段定性（装在哪、跑什么、共享什么、数据在哪）+ 位置段（先行者与空白，
定位篇已拍的口径此处引用不复证）。
#### {核心概念}的分层
从定位篇的概念辨析继承，压缩成分层清单 + 一句类比金句。
（判据：与定位篇逐字不冲突；金句能当全文引语。）
#### 交付分 N 段
阶段清单 + 定调句：第一阶段是地基，治理/终局在后续阶段。
（判据：阶段划分与定位篇路线图一致，不另立口径。）
### 1.2 {项目名}能干什么
核心能力逐条小节，每条带「基于这个能力可以做的事」；末尾放一张
能力组合场景表。
（判据：能力条目与定位篇核心能力一一对账；场景表覆盖全部能力。）
### 1.3 文档定位
三档分级：核心功能 / 扩展功能 / 社区共建功能 + 范围基准一句
（第一阶段边界拿什么定的）。
（判据：范围基准与第 0 步拍板一致。）

## 2. 术语和概念
术语表，一行一个：定义本体术语放第一行。
（判据：与定位篇概念辨析逐条一致；正文用词不出此表。）

## 3. 设计目标
3~5 个词，每词一行说明。
（判据：每个词都能在核心功能章找到承载它的功能。）

## 4. 典型场景
2~3 个完整形态（含扩展阶段能力）场景，逐个注明「本阶段先具备其内核」，
每个场景写清 {项目名} 在其中的角色。
（判据：场景是目标用法不是现状承诺；第一阶段做不完的部分标注清楚。）

## 5. 核心功能
引语：第一阶段必须完成的最短链路 + 一句完整链路描述（配一个 Agent/任务 →
对话 → 调工具 → 触达 → 对外暴露）。
每个能力一节（工作区/定义方式等基建能力排前），每节带：
- 清单级内容（端点表、命令表、结构示例、参数说明）
- 「第一阶段不做」清单
（判据：粒度到端点/命令/字段级；「不做」清单与扩展章对得上；
无选型论证。）

## 6. 扩展功能
分层罗列（渠道模型 / 记忆能力 / 工具安全 / 治理运维 / 企业集成，按项目裁剪）。
（判据：每条都能回答"它从核心功能的哪个「不做」接过来"。）

## 7. 社区共建功能
长期方向清单，不规定时间表。
（判据：与扩展功能分得清——扩展在生产主线上，共建不在。）

## 8. 非功能需求
性能（数值表）/ 可靠性 / 可运维性 / 兼容性 / 安全 / 合规。
（判据：性能指标给数值并注明不可控项；安全与合规里"核心已做"与
"扩展补齐"分得清。）

## 9. 关键流程
3~5 条端到端流程（初始化、创建启动、最高频链路必在），流程图式文本。
（判据：最高频链路覆盖全部触发源；每步动词开头、可走通。）

## 10. 数据模型
持久化对象逐一给表字段（字段/类型/说明），文件形态对象注明无 schema。
（判据：与核心功能章的对象一致，无正文没提过的表。）

## 11. 里程碑规划
形态按拍板：时间盒（周/单元 + 能力主线 + 可演示成果表）或交付单元
映射表（节奏自定）。附范围溢出规则（某单元完不成时挪什么到扩展）。
（判据：每行有可演示成果；能力主线覆盖核心功能章全部小节。）

## 12. 风险与未决事项
风险表（风险/描述/应对）+ 未决表（事项/说明/决议时间）。
（判据：选型类开放问题全部收在未决表且注明决议时间——这是 What/How
分界的泄压阀。）

## 13. 验收标准
功能验收（checklist，与第 5 章小节一一对应）/ 性能验收（对第 8 章数值）/
可运维性验收 / 场景验收（端到端 Demo 表；拍板为硬条件则明写硬条件）。
（判据：checklist 无一漏项、无一超范围；Demo 覆盖全部核心能力与触发源。）

## 14. 总结
是什么 / 交付分几段 / 核心能力清单 / 核心理念。
（判据：与第 1 章口径零漂移；核心理念一段话能独立当摘要用。）
```

两条全文判据：

- 通读一遍：每一节要么在立范围、要么在立边界、要么在立验收——定位论证复读、营销话术、选型论证出现即删（选型进未决表）。
- 对账三查：能力清单与定位篇一致；术语与术语表一致；验收项与核心功能小节一致。显式偏差逐处留有拍板理由。
