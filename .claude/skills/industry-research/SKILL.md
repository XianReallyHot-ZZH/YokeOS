# 业界调研（立项定位型）

帮用户完成立项级业界调研：产出一份定义先行、证据可溯源、收敛到定位锚点的调研文档。适用的是"为定位一个新产品/新项目而调研一个品类"；选型对比、单点事实查证是别的活。

两条铁律贯穿全程：

1. **未拍板不动笔**。框架口径（对象、时间、读者、收口）是用户的决策；拍板前只出提纲和证据，正文一字不写。
2. **无来源不落数字**。每个数字带来源 URL 和日期；查不到就降级表述，编造是本 skill 的唯一死罪。

## 第 0 步 · 拍板

完成判据：四个口径问题用户全部给出明确答案，缺一个不进第 1 步。

1. **调研对象**：一句话说清调研的品类（"面向 X 的 Y"）。
2. **时间口径**：以今天为时点，如实直面在位者——包括对用户预设不利的在位事实。
3. **读者与用途**：给谁看、支撑什么决策（立项文档链首篇？内部 go/no-go？）。
4. **收口决策**：这份调研最终要拍板什么（定位锚点？进不进这个品类？）。

用户没头绪时，给默认问题集再逐个确认：①品类定义 ②格局与代表玩家 ③需求论证 ④本项目/本生态的位置 ⑤定位锚点。有真实分歧的口径用选择题（AskUserQuestion）拍板，其余按默认走。

## 第 1 步 · 定义先行

先造尺子，再量东西。写成三件套：

- **品类定义**：是什么、装在哪、为谁服务。
- **要件清单**：合格的 X 必须具备哪几件事（4~6 条，后续所有竞品评析拿它量）。
- **相邻概念辨析**：一张表分清 X 与最容易混的 2~3 类东西（产物/使用者/跑在哪/锁定程度）。

完成判据：用户确认尺子。尺子错后面全错，这是最便宜的一次纠偏机会。

## 第 2 步 · 并行取证

按尺子分路收集，互相独立的路放后台 agent 并行：

- **格局路**：代表玩家逐一画像（规模/取向/强项/软肋/一句话定位），清点四类：在位者、新入场者、已退出者、蹭名称的噪声项（识别并说明排除理由）。
- **需求路**：大盘采用数据、试点到生产的断层、阻塞点排序。
- **监管路**（严监管品类才开）：合规条文与时间线、数据主权约束。

取证纪律（每路同款）：

- **一手优先**：官方仓库 API、官方博客、监管原文、报告原文；star 数、版本号走 API 实抓。
- **回溯到源头**：搜索摘要只是线索，对其中每个数字回溯到拥有它的源头再引用。
- **标注未核实**：仅见于二手转述的数字，显式标注并保守表述。
- **时间悖论检查**：主动检索推翻任务预设的证据——在位事实、品类被巨头收编、预设的空白已被填上。找到就上报用户重新拍板口径，不硬写。

完成判据：每个数字可溯源（URL+日期）、四类玩家清点完毕、时间悖论检查跑过。

## 第 3 步 · 空白即定位

调研的收口是一个空白，不是一堆数据。把格局摆到尺子上回答：**还没有任何人填的位置是什么？** 用一句话说出来。说不出来就回第 0 步重新拍板——"业界现状总结"不是空白，不许拿它交差。

完成判据：一句话空白，且经得起两个检验——拿尺子量它成立；它恰好是收口决策要的那个位置。

## 第 4 步 · 锚点拍板

从空白导出 2~3 个锚点选项，过**锚需求不锚概念**检验：锚点锚在不会变的需求（合规、成本、数据主权、技术栈存量）上，还是锚在可能被稀释、被改名的概念上？过不了的锚点不进选项。选择题交用户拍板。

完成判据：用户选定锚点。

## 第 5 步 · 成文

按 [doc-structure.md](references/doc-structure.md) 的骨架成文。骨架可按调研对象裁剪，两样东西不可省：来源清单附录、数据时效注。

## 第 6 步 · 沉淀

- 调研中自造的词：仓库有词汇表惯例（如 CONTEXT.md）就按惯例沉淀，没有就跳过。
- 口径决策若同时满足三条——难逆、无上下文会困惑、真实取舍——记一条 ADR；差任何一条就不记。
