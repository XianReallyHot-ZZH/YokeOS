# AI 编程指南骨架（立项期）

立项期过程约束文书的章级骨架，提炼自先行者立项指南的公共形态并补齐其缺位：双模式前置、输入映射表、宪法治理含同步清单、门禁双轨、证据化验收。每节括号内是成文判据，写完一节对一次。目标密度：三百~五百行级——厚度来自工作流步骤、条款、纪律、证据项的穷举，不来自方法论论述；发现同一段方法论布道出现两次，删。

```md
# {项目名} AI 编程指南

> 引言块：本文定义 AI 编程实施思路，回答"用什么方式做"——人机分工、流程选型、
> 门禁与验收证据。主体思路一句话：{规格工具链}完成主体开发，把上游文档喂给它，
> 按{上游里程碑形态}逐单元实施；增量阶段切手动提示词。
> 前置阅读：调研、定位、需求、技术方案。
> 以最新技术方案为准 + 喂下游的必须是最新版。
（判据：读者看完引言块就知道双模式分界与文档消费关系；粒度上限——不写设计与选型。）

## 1. 实施总览

### 1.1 主体思路：双模式
表：阶段/协作模式/适用场景；边界规则 = 流程开销与工作量之比；大 feature 例外
（新增模块、改宪法、跨核心能力仍走完整流程）。
### 1.2 跟上游文档的关系
输入映射表：流程输入/来源文档/作用——spec 输入←需求篇对应单元、plan 输入←
技术方案对应章节、宪法←设计目标+关键决策、单元完成判据←里程碑表可演示成果、
阶段验收←验收标准与端到端场景。
### 1.3 拆解策略
拆解单位 = 上游里程碑单元（与需求篇同构，引用不重抄）；核心能力做骨架层
（依赖关系一句话图）；单元类型不均齐的显式点名；不用 P1/P2/P3 优先级标记，
排后 ≠ 可不做，依赖序才是推进序。
### 1.4 工具匹配度评估
表：评估维度/本项目情况/匹配度——诚实对照工具适用与不适合场景，后者逐条给化解。
（判据：拆解单位与上游里程碑同构；输入映射表覆盖全部流程环节；
匹配度含"不适合"行的回应；能力主线表零重复抄。）

## 2. 工具链（与对照层）

### 2.1 规格工具链与使用纪律
版本锁定（整个主体开发期不升级）、只用官方核心命令、一次只推进一个单元；
具体命令形态以实施时官方文档为准。
### 2.2 单元级工作流
一览：备料 → spec → 澄清 → plan（人工定向 review）→ tasks（固定停点）→
implement（写前/写中/写后）→ 收尾（证据化 DoD + 验收报告 + 变更总结）；
固化成可执行 skill 的时机显式写。
### 2.3 方法论对照层（可选支线：项目以过程差异化为承诺时）
对照轴 + 映射表落点 + 每单元验收报告一节；不进主流程、不叠加门禁。
（判据：命令细节零锁定；纪律可执行；固化时机显式。）

## 3. 准备阶段（首个实施单元开工前）

### 3.1 工程地基初始化
交付清单（模块骨架/基础组件/门禁全链路/建表预留位）+ 验证标准（机器可判：
verify 全绿、起得来、故意违规要红）+ 与宪法/CI 的分工一句。
### 3.2 项目宪法
条款表（#/原则/规则/rationale），「最易被写错」的条目标注；治理条款：
写一次定下来、AI 不得自改、语义化版本修订、**修订同步清单显式包含本指南与
运行时 AI 指南**、与运行时指南双向一致。
### 3.3 单元级输入映射
「单元 ↔ 权威文档章节」映射表写死——让"读对应章节"可执行而非凭感觉。
### 3.4 运行时 AI 指南
收编宪法运行时版（模块表/数据模型/工作机制）+ 常见陷阱表从第一天记 +
飞轮一句（陷阱→review 检查单→回归测试→高频升格宪法/不变量）。
### 3.5 准备阶段交付物清单
目录树（.specify 或等价物/宪法/工程地基/运行时指南/工作流 skill）。
（判据：宪法每条有 rationale；同步清单条款在；地基验证标准机器可判；
映射表覆盖全部实施单元。）

## 4. 逐单元实施

### 4.1 单元级工作流（步骤化，每步挂门禁）
0 课型/单元类型分流 → 1 开工纪律（三读：当节上游行+权威章节+前序交付物；
依赖存在性核对；分支确认）→ 2 spec（六段式骨架，只 WHAT/WHY 不带类名与技术栈，
「不做」逐项照搬）→ 3 澄清（可选；答案只从上游找，找不到=软门禁）→
4 plan（固定技术栈句+模块落位+测试策略+语法禁区；生成后人工定向 review，
通过才锁定）→ 5 tasks+固定停点（任务↔交付物清单自动比对，测试先行，停等确认；
授权颗粒度 = 回滚颗粒度）→ 6 implement（写前 API 核实/写中保真与质量/
写后任务级 DoD 红了当场修）→ 7 收尾（证据 DoD + 报告 + 对话内总结，停止等 commit）。
### 4.2 单元类型分流表
产码单元走完整流程；评审类拒绝产码、产出文档喂下一单元 spec；
串联类不开新规格、固化集成验证；演示类只做真实运行与发布。
### 4.3 单元拆解模板与重点单元
每单元从三份现成材料拼装（上游里程碑行/技术交付物行/模块表），不另写拆解文档；
三份之外的新概念=软门禁。任务颗粒度最重的 2~3 个单元预先点名易错处
（对应宪法标注的那几条）。
### 4.4 实施协作模式
一致性检查的跑法与必跑时机；跑偏纠正表（跑偏/正确做法两列，从宪法推导，
实施中发现的追加进陷阱表）；上下文回充（再入场三读+长序列固定触发器重读）；
commit 锚点（AI 不自动 commit、提交颗粒度=回滚颗粒度、每单元一分支、
合流点重跑全量门禁且前序全绿为前提）。
（判据：每步有门禁挂点；跑偏表条目可从宪法推导；固定停点唯一且明确；
六段式是单元级模板、不套给项目级需求。）

## 5. 门禁体系

### 5.1 双轨门禁
判定标准一条：机器能不能判。硬门禁族（格式/规约/静态分析/安全扫描/CVE）
全链路接入构建，测试纪律一句（入口模块不豁免类）；静态检查=门禁，
解析失败=构建失败，工具链兼容性条款（宁禁语法不开洞）；
人不做格式类 review。
### 5.2 软门禁「必须停下」清单
枚举 5~6 条：清单外交对外概念/改已定字面量/权威文档冲突/改前序公共接口/
核实不到的第三方 API/plan 外依赖。批准落文档闭环：放行设计变更列受影响
文档清单逐个确认（含技术方案及其架构图——图随文改）。
### 5.3 门禁骨架表
H0 开工纪律 / H1 设计保真（文档优先、不做清单同等硬度）/ H2 跨单元契约 /
H3 API 真实性 / H4 全局不变量 / H5 实现质量 / H6 完成定义，各一行挂点与管什么。
### 5.4 全局不变量
5~8 条"无论做哪个单元永远成立"，逐条可 grep 或可测试；多入口同链路类
约束在此落静态形态。
### 5.5 反作弊条款
不得删断言/跳过/放宽阈值让测试变绿；未全绿不得宣称完成。
（判据：每条纪律归轨明确；停下清单是枚举不是品行要求；不变量逐条机器可核。）

## 6. 验收与证据

### 6.1 单元级验收报告
证据项模板（构建全绿/回归对号/交付物存在性核对/前序回归/全局不变量自查/
人工项清单），可选增节：门禁拦截记录（过程差异化的直接证据）、方法论对照
（对照层支线启用时）；落盘位置与命名。
### 6.2 变更总结
对话内导读、不落盘（描述这一次的 diff，落盘即过期）；三段固定结构：
改动点/重点 review 清单/验证命令块。与验收报告是两个 named 交付物，不合并。
### 6.3 对账法与集成固化
集成阶段启用：真实调用逐表对账（该留的留下/不该留的没多出来/同源一致）；
清单稳定后固化成集成测试；默认排除、显式触发时机写明。
### 6.4 阶段验收
引上游验收标准与端到端场景，硬条件声明；与阶段总结/复盘的分界一句
（后者不在本篇范围）。
（判据：验收资产逐项有证据形态；两个 named 交付物分野清楚；
集成测试触发时机显式；每单元判据引上游不另立口径。）

## 7. 增量阶段：手动提示词模式
主体 vs 增量对比表（颗粒度/跨模块协作/上下文/宪法与 spec 的角色）；
增量工作流（认领→改→测→PR）；宪法与既有 spec 长期有效、验收标准是回归底线；
大 feature 回完整流程。
（判据：切换条件显式；长期参考物点名。）

## 8. 风险和注意事项
工具链风险表（版本锁定/官方文档随时查/扩展谨慎/spec 不同步→一致性检查）
+ 常见挑战对策表（跑偏/上下文断裂/停点被跳/外部集成踩坑/演进机制弱项/
门禁兼容性/工程基础前提）。
（判据：对策列引用正文章节，不另立机制。）

## 9. 总结
双模式一句话；三~四条主线（喂上游不重写且喂最新版/宪法非协商含同步清单/
门禁双轨机器先判/做完是证据不是感觉）；与项目过程差异化承诺的呼应一段。
（判据：与第 1 章口径零漂移；总结能独立当摘要用。）
```

两条全文判据：

- 通读一遍：每一节要么在立流程、要么在立纪律、要么在立门禁、要么在立证据形态——方法论布道、需求复读、设计重述、工具命令细节出现即删。
- 对账四查：技术方案关键决策逐条有宪法承载或显式不收的理由；需求篇「不做」清单全部进禁令或门禁；每条纪律可归入"机器判"或"停下问人"；验收资产每项有证据形态——四查全过才交。
