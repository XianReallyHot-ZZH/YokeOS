# YokeOS 逐节开发 Skill

## User Input

```text
$ARGUMENTS
```

节号来自输入。流程依据 `docs/AiProgrammingGuide.md` §4.1 七步工作流与 §5 门禁体系；
**worked example**：`specs/001-provider-abstraction/` 全套产物（第 16 节实走，2026-09-11）——
组装形态、停点输出、验收报告结构一律照它。条款以本文为准执行。

## 总纪律（贯穿全程）

> **能机器判的绝不留给人，机器判不了的绝不自行发挥。**

- **硬门禁**：测试、`mvn clean verify`、存在性核对——不过不放行，不许绕。
- **软门禁**（任一命中→立即停下、报告、等用户确认）：① 需要创建教学文档「本节交付物」清单之外的
  对外概念（public 类型 / 配置键 / 数据表 / REST 路径 / Profile 字段）；② 需要修改已定字面量
  （类名 / 方法签名 / 配置键 / 表列名 / 端点路径）；③ 文档链内部冲突（含教学文档 ↔ 技术方案 ↔
  宪法之间的张力——修文档优先，参照第 16 节 llm_calls 补列先例）；④ 改前序节公共接口（当节明确
  列为改造点的除外）；⑤ 第三方 API 本地依赖核实不到；⑥ 需要新增 plan 未列依赖（传递必需件记理由
  放行，写进验收报告「实施偏差」节）。
- **反作弊**：不得删断言、`@Disabled`、放宽阈值让测试变绿。实现错修实现；认为测试错，停下报告。
- 宪法 `.specify/memory/constitution.md`（v1.0.0）只读——AI 不得自改，修订属设计变更。
- 全程**不自动 commit / push**；建分支、commit、合流均由人决定。

## 第 1 步 · H0 开工纪律

1. **三读**（Read 完整读，不凭记忆）：当节教学文档（glob `docs/class/{NNN}-*.md`）；技术方案
   对应章节（映射表见下）；需求文档 §11 当节行 + 技术方案 §13 前序各行。
2. **依赖存在性检查**：前序交付物核心类逐个 grep/Glob 确认存在；缺失→停下报告「先做第 X 节」。
3. **分支**：`git checkout -b specs/{NNN}-<slug>`（手动建——specify 1.0.4 的 git extension 未启用），
   不在 master 上直接开发。
4. **可选参照**：参照课件可从 submodule 历史取阅
   `git -C vendors/oryxos show '8f12f11^:docs/class/第{N}节：<标题>.md'`——结构照抄、语义参照，
   不抄代码（API 有代差）。

## 第 2 步 · 组装并执行 /speckit-specify

从教学文档**一、二部分**按六段式骨架组装参数（只写 WHAT/WHY，**不带 Java 类名**；表名、文件名、
配置键、命令名等产品级字面量保留）。骨架与成品对照 worked example 的 spec.md：

```text
第{N}节需求：<模块名>——<一句话定位>
背景与价值。<从「一、是什么」提炼>
用户场景。<2~3 个，从需求文档 §5 对应能力章取>
功能需求。FR1~FRn <每条可测试>
明确不做（边界）。<教学文档「有几样先别做」逐项照搬>
验收标准。自动化部分由验收 harness 承载（mvn test 全绿），关键回归点逐条点名；人工项单列
依赖与假设。<前序交付物；外部依赖如 BOM/MCP server>
```

## 第 3 步 · /speckit-clarify

有问题答问题——**答案只从需求文档 / 技术方案 / 教学文档找**；找不到→软门禁停下问用户。
每答即回填 spec（Clarifications 节 + 对应 FR / 场景措辞同步改）。

## 第 4 步 · 组装并执行 /speckit-plan → 停等人工定向 review

参数 = 固定技术栈句 + 模块落位 + 测试策略句 + 语法禁区句：

**固定技术栈句**：`JDK 21 + Spring Boot 3.5.16 + Spring AI 1.1.8 + Spring AI Alibaba（仅协议转换 +
@Tool schema 生成，禁自动 tool 执行与 eager 自动装配；动手前 mvn dependency:resolve -am 核实 BOM 可解析
——参照课程期 3.3.5/1.0.0-M6 存在 API 代差，写法以 1.1.8 本地依赖 javap 核实为准）+ SQLite
（sqlite-jdbc 3.53.2.1）+ Spring Data JPA + hibernate-community-dialects。凭证走 ${ENV_VAR} 占位
不落明文。SQLite 手工建表脚本，不走 ddl-auto=update。`

**模块落位** = 技术方案 §13 当节行 + §10 模块表展开；**测试策略句**从教学文档第四部分整段抄
（测试类清单 + 关键回归点 + 「实现完成的定义是 mvn clean verify 全绿」）；**语法禁区句**：
`避开 P3C/ASM 解析不了的 Java 18+ 语法形态；测试类名 ≤1 连续大写（冒烟类用 …IntegrationTest
不用 …IT）；日志消息必须编译期常量（CRLF 注入门禁），动态内容进异常堆栈。`

**plan 生成后停下**，人工定向 review（指南 §3.4 四问：Memory 被简化合并？Tool 被拆模块？AGENT.md
被当 Tool？自动执行被启用？）+ worked example 增补一问：是否引入了带 autoconfigure 的 starter
（宪法 2 eager 装配坑）。用户说「锁定」后才进第 5 步。

## 第 5 步 · /speckit-tasks + 固定停点

调用时**显式喂 TDD 纪律参数**（不喂则不生效，试跑硬情报）：

```text
TDD 纪律：测试任务先于或伴随对应实现任务（验收 harness 先行），实现与测试在同一任务内闭环、
该模块测试红了当场修；集成冒烟单列。测试方法名用英文，教学文档语义以 @DisplayName 保留。
```

任务生成后**自动比对**：任务 ↔ 教学文档「本节交付物」逐项（缺什么/多什么）+ 测试是否先于实现。
输出比对结果，**停下等用户确认**——全流程唯一固定停点，不许跳过。

## 第 6 步 · /speckit-analyze（固定）→ /speckit-implement

analyze 必跑（试跑硬情报：产码前抓字面张力），MEDIUM 以上先修再 implement。

implement 实操纪律（worked example 沉淀）：

- **写前（H3）**：新依赖先 `mvn -pl <模块> -am dependency:resolve`；Spring AI 写法用
  `javap -p -classpath <jar> <类>` 核实签名后再落笔。
- **写中（H1/H5）**：注释中文为主、技术术语保留英文；每文件落盘后立即 `mvn -q -pl <模块>
  spotless:apply`；异常不吞；单实现不建接口。
- **写后（任务级 DoD）**：`mvn -pl <模块> -am test` 红了当场修；任务完成即勾 tasks.md `[x]`。
- **命令形态**：单模块构建必带 `-am`（reactor）；集成测试显式触发
  `mvn -pl <模块> -am test -Dgroups=integration -DexcludedGroups=`（覆盖 pom 默认排除）；
  冒烟缺真 key 时 `assumeTrue` 跳过并注明，不失败。

## 第 7 步 · 收尾——六项证据 DoD + 验收报告 + 变更总结

全部满足才可宣布本节完成，逐项写进 `specs/{NNN}-<slug>/acceptance-report.md`
（结构照 worked example）：

1. `mvn clean verify` 九模块全绿（贴关键输出与测试数）；
2. 教学文档 harness 映射表逐测试类对号，关键回归（坑↔测试）逐个过；
3. 「本节交付物」逐项存在性核对（ls/grep 证据）；
4. 前序节全部测试回归绿（合流前在 feature 分支跑）；
5. **H4 七条全局不变量逐条自查**（可 grep / 可测试；Sandbox 未就位节留位注明 24 节接线；
   session 拼接按 18 节判；新触发入口按 17 节判）；
6. 人工项**当场跑完**（真 key 冒烟、`grep sk-` 凭证卫生、init/幂等抽查）+ 剩余项清单
   （理想为零）。

收尾附加动作：**实施中新坑一条一行回填 CLAUDE.md 常见陷阱表**（宪法 7 节纪律，第 16 节回了
3 条）；实施偏差（改名 / 依赖增补 / 落位调整）记验收报告「实施偏差」节。

最后输出**变更总结**（对话内，不另开文件，三段固定结构）：
- **改动点**：按模块分组，新增/修改/删除各一句动机；前序节被触碰处单独标出；
- **重点 review 清单**：按风险排 3~6 条，架构与宪法落点优先，给文件行级定位；
- **如何验证**：可复制命令块（全量门禁 / 本节测试 / 冒烟 / 不变量 grep），每条注明预期。

报告完**停止**——commit、合流（`--no-ff` + 合流点重跑全量门禁）、push 由人决定。
