# AI 编程指南（立项文档链第五篇）

帮用户把"怎么用 AI 把它做出来"写成一份过程约束文书：人和 AI 各管什么、按什么流程走、哪些决定不许改、做完了拿什么证明。它是立项文档链的收口篇——上游四篇冻结决策，本篇冻结**执行方式**：宪法条款集、门禁体系、工作流与验收证据形态。它是研发实施与未来节级开发 skill 的直接依据，不是编码风格手册（那由工程地基的门禁工具承载），也不是需求或设计的复读。

用户此刻通常在构思规划期：手里有上游文档（甚至只有能力清单与关键决策意向），没有代码、没有实施反馈。默认路径只依赖上游输入与用户拍板；凡是依赖既有资产或参照仓库的步骤，先确认存在才走。

三条铁律贯穿全程：

1. **未拍板不动笔**。拆解形态、宪法条款集、门禁收法、验收证据形态是用户的决策；拍板前只出提纲和输入清单，正文一字不写。
2. **流程契约，不锁命令**。指南锁流程、门禁与证据形态；工具的具体命令、安装方式、artifacts 格式一律以实施时官方文档为准，只写使用纪律（如版本锁定）。工具迭代快，锁了命令细节的指南过一版工具就失真。
3. **拆解单位跟上游里程碑走**。上游需求篇的里程碑表（节序映射、时间盒、能力分期）是拆解的直接上游——指南不另立拆解口径，只补"每个单元怎么干、干完拿什么证明"的层；重复抄上游的能力主线表是本 skill 的事故高发区。

## 第 0 步 · 拍板（口径）

完成判据：四个口径问题用户给出明确答案，缺一个不进第 1 步。

1. **上游输入**：第四篇技术方案在手吗？它的关键决策表是宪法的直接原料，它的"遗留未决"里有没有移交本篇固化的条目（如原则条款落点）？第三篇需求篇在手吗？它的里程碑形态与验收标准是拆解与证据链的原料。只有部分上游但用户有明确决策清单：列为输入，显式标注「未经完整链固化」。
2. **范围对齐**：第一阶段边界沿用需求篇的范围基准，本篇不重定范围；「不做」清单在本篇的去向是门禁（同等硬度的禁令），不是被遗忘。
3. **形态参照**：有先行者（或参照项目）的 AI 编程指南可对照吗？拿得到原文与 git 演化史吗？拿得到则第 1 步加走考古支线；拿不到则用 references/doc-structure.md 的通用骨架。
4. **落点与分界**：指南落在哪、给谁看（实施者 + AI agent 的执行契约？）。与第四篇的分界拍一下：**同一原则两篇都出现时，第四篇写设计语义，本篇写执行语义**（如某技术决策在第四篇是选型理由，在本篇是"违反会发生什么、怎么拦"的宪法条款）。

## 第 1 步 · 输入提炼（有形态参照加考古支线）

**通用部分**——把上游输入提炼成五类清单，交用户过目：

- **实施单元清单**：上游里程碑表的每一行（单元号、类型、完成判据）——本篇工作流与拆解的骨架；单元类型不均齐的（评审类/串联类/演示类不产码）单独标注，第 2 步要拍分流。
- **宪法原料**：技术方案关键决策表逐条列出——每条都是候选宪法条款；标注哪些是"AI 很容易顺手做错"的边界决策（这类优先升格），哪些交给门禁工具就够。
- **验收资产**：需求篇验收标准、端到端场景、每单元可演示成果——证据链的原料，第 3 步逐项给证据形态。
- **执行现状**：团队用什么 AI 工具、已有哪些流程资产（skill、模板、CI）、单人还是多人——双模式的边界与门禁分轨的输入。
- **边界与排除**：需求篇全部「不做」清单——软门禁与"禁令同等硬度"条款的原料。

**考古支线（仅拿得到参照指南原文与提交历史时走）**：

- `git log --follow` 找参照指南的最早提交，`git show <hash>:<path>` 读首版，再读立项期末版与现版——首版与期末版的 diff 直接回答**文档与实现关系类型**：逐字节相同 = 立项期零回写的滞后补账型；持续演进 = 逐节同步型。
- 四层提取：**骨架层**（双模式结构、输入映射表形态、匹配度评估、跑偏纠正表——可抄）；**粒度层**（工作流步骤、停点位置、证据清单条目的写法——可抄）；**决策层**（具体拆解、条款、门禁族——跟参照的项目走，不照抄）；**滞后层**（现版残留的旧形态：条款数与实物不符、拆解单位与实际执行单位脱节、措辞过期）。
- **滞后归因（本支线独有的价值）**：对每处滞后点问"制度根源在哪"——最常见的一处是**修订同步清单没包含本篇**（宪法或权威文档的 Sync/受影响清单漏列指南，导致指南成为唯一不回写的文档）。归因结论进第 2 步拍板与第 3 步正文，正文不评价参照文档质量（产品口径）。
- 完成判据：五类清单（+ 考古四层表与滞后归因）交用户过目。

## 第 2 步 · 框架拷问

拍板点用选择题（AskUserQuestion）逐个过，未拍板不动笔：

1. **拆解形态**：按上游实施单元拆（与需求篇里程碑同构）/ 按能力拆 user story（先行者形态）/ 双层。默认上游赢——拆解单位与上游里程碑脱节的指南，实施时必然二次翻译。能力依赖关系做骨架层，不与单元冲突。
2. **宪法条款集逐项拍板**：关键决策怎么升格（逐条直译 / 合并同类收敛为 8 条左右——超过 15 条说明还没想清哪些真正不可协商 / 更精简）；候选条款逐条过（规则 + 一句话 rationale + 「最易被写错」标注）；**增补候选逐条拍归层**——收宪法（架构边界级）还是落正文纪律层（一致性/文档纪律级），不收不等于丢。宪法治理条款必含：AI 不得自改、语义化版本修订、**修订同步清单显式包含本指南与运行时 AI 指南**。
3. **工具链落法**：指南立流程契约的粒度——阶段序、输入映射（哪份文档喂哪个环节）、固定停点位置；工具命令细节全部推给官方文档；工作流固化成 skill 的时机显式写（通常：流程手动跑顺后、首个实施单元开工前）。
4. **门禁集**：硬门禁族收法三选——宪法点名门禁族不锁版本（先行者宪法实物形态）/ 宪法只收"全链路全绿方可合并"抽象条款 / 全部推迟到工程地基；工程地基时机显式拍（通常：首个实施单元开工前一次性配好）。机器判不了的一律进软门禁「必须停下」清单，逐条过。
5. **验收证据形态**：单元级验收报告的证据项（从验收资产推导，通常含：构建全绿、回归测试对号、交付物存在性核对、前序回归、全局不变量自查、人工项清单）；变更总结是否单列（对话内导读 vs 落盘）；跨单元契约的对账固化时机（集成阶段）。

完成判据：全部拍板点有明确答案。

## 第 3 步 · 成文

按 [doc-structure.md](references/doc-structure.md) 的骨架成文。四条写作纪律：

- **执行语义**：宪法每条 = 规则 + rationale（违反会发生什么具体坏事）；纪律每条可执行（可 grep、可测试、或可枚举的停下条件），"保持专注""严守规范"这类不可执行的表述出现即删。
- **滞后修复前置**：考古支线发现的滞后归因（如同步清单漏列）直接写成本篇的治理条款；没有参照的项目也要预防性写入——它是这类文档腐烂的头号根源。
- **单元不均齐就显式分流**：评审类不产码产文档（产出的文档喂下一单元的 spec）、串联类不开新规格只固化集成验证、演示类只做真实运行——分流表进正文，不在工作流里塞特例。
- **产品口径**：过程型、学习型元语境不进正文；参照与先行者可事实性引用（已验证的工具组合、公开的交付窗口）。项目若以过程差异化为承诺，可选设「方法论对照层」支线：对照轴 + 映射表落点 + 每单元验收报告的一节，不进主流程、不叠加门禁。

## 第 4 步 · 对账自检

写完逐项过，任何一项不过就改文，不带病交付：

- **宪法完备**：关键决策表每条在宪法有承载，或显式记录"不收的理由与去向"；每条有 rationale；最易写错点有标注；治理条款齐（不自改/版本化/同步清单含本篇）。
- **拆解一致**：拆解单位与上游里程碑同构；单元类型分流有表；上游能力主线零重复抄。
- **门禁双轨无悬空**：每条纪律可归入"机器判"或"停下问人"之一；停下清单是枚举条目不是品行要求；批准落文档的闭环在（受影响文档清单含本篇与运行时指南）。
- **证据链闭合**：验收资产每一项有证据形态承载；证据项逐条机器可判或显式列人工项；反作弊条款在；提交与分支纪律在（提交颗粒度 = 回滚颗粒度）。
- **命令零锁定**：全文无具体工具版本号承诺（版本锁定纪律本身除外）、无会随工具版本失效的命令细节。
- **滞留检查**：考古滞后的每一处，本篇要么已修复（条款化）要么确认与本项目无关。

完成判据：六项全过。

## 第 5 步 · 沉淀

- 与先行者形态的显式偏离、宪法条款的取舍争议若难逆且无上下文会困惑，记一条 ADR。
- 遗留交接：工程地基清单（何时配、含什么）、运行时 AI 指南（CLAUDE.md/AGENTS.md）的收编时机、工作流固化成 skill 的触发时机——逐项注明时机，它们都不在本篇范围内执行。
- 成文或对账中发现与上游文档冲突：停下来报告用户，既不擅自改上游也不硬写。
