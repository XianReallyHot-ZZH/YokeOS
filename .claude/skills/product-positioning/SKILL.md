# 产品定位（立项文档链第二篇）

帮用户把定位输入收敛成一份短而密的定位文书：项目是什么、为什么需要它、守什么原则、不做什么。它是立项期的定位宪法——不是营销页，不是需求清单，不是技术方案，那三样分别是 README 和链内后三篇的事。

用户此刻通常在新项目的构思规划期：手里往往只有第一篇调研（甚至只有想法），没有代码、没有历史、没有治理文档。默认路径只依赖定位输入与用户拍板；凡是依赖既有资产的步骤，先确认资产存在才走。

两条铁律贯穿全程：

1. **未拍板不动笔**。框架口径（定位模式、五拍板点）是用户的决策；拍板前只出提纲和输入清单，正文一字不写。
2. **无上游不立论**。能力清单、论证数字、概念命名，每个事实性断言都能指向上游——第一篇调研、项目治理文档、或可核验的一手事实。找不到上游就回调研补证，不硬写。

## 第 0 步 · 拍板（口径）

完成判据：四个口径问题用户给出明确答案，缺一个不进第 1 步。

1. **定位输入**：第一篇调研在手吗？
   - 在：它的空白句、锚点、概念定义（尺子）、需求论据就是输入。
   - 不在，但用户已有明确定位结论（既定方向、已想清楚要做的事）：列为输入，显式标注「未经调研验证」，第 2 步拷问时提示补检验。
   - 两样都没有：建议先走 industry-research。本 skill 不替调研，没有输入不凭空成文。
2. **定位模式**：本项目以什么方式进入品类？
   - **原创进入**（默认）：调研认定的空白就是自己的位置，与先行者各走各路。
   - **参照进入**：明确以某个先行者为镜（对标、复刻、站在其肩膀上）。此模式加走第 1 步的参照考古支线，且需要拿得到参照仓库——拿不到就如实降级为公开资料对照，考古做不了的部分说明即可，不脑补。
3. **对账对象**：项目有词汇表、治理文档（ADR / 范围决策）吗？有则记下位置供第 4 步对账；没有则本篇就是它们的起点，第 4 步只对上游输入与分工边界。
4. **落点与读者**：定位篇落在哪、给谁看（仓内宪法？对外首页素材？）。

## 第 1 步 · 输入提炼（参照进入加考古支线）

**通用部分**——把定位输入提炼成四类清单，交用户过目：

- **空白句**：调研收口的那句「还没有人填的位置」，定位一句话的地基。
- **锚点**：调研拍板的锚，连同被否掉的锚一起记——防止愿景拍板时翻案。
- **尺子**：调研的概念定义与相邻概念辨析，第 4 节词汇立宪的原材料。
- **论据**：需求论证最硬的三五条数据（带来源与日期），「为什么需要」只引用不重证。

**参照考古支线（仅参照进入且拿得到参照仓库时走）**：

- 挖立项期首版：`git log --follow` 找参照定位文档的最早提交，`git show <hash>:<path>` 读原文，再读现版。
- 修订史三分类：**概念层**（命名、公式、句式）、**论证层**（「为什么需要」的依据）、**锚层**（原则、路线骨架、不变锚点）。
- 可抄性判定：锚层可继承；概念层跟本项目产品形态走，不照抄；论证层**不可抄已被参照自己证伪的版本**——参照上线后被迫改写的论证，立项期版已失效，从第一天写当下诚实版。
- **参照仓库的现状不算来源**：它混着立项期内容与后续演化，拿现版当立项形态照抄是最常见的死法。

完成判据：四类输入清单（+ 考古三分类表）交用户过目；与调研矛盾或缺位的事实回报用户，不自行吸收。

## 第 2 步 · 框架拷问

五拍板点用选择题（AskUserQuestion）逐个过，未拍板不动笔：

1. **定位一句话口径**：纯定性一句，还是加终局动作链？动作链只在本项目能力清单撑得到时才写——参照进入时对照考古结论（参照的动作链是立项期就有还是交付后才长出来的），不凭参照现版印象；原创进入时不预支未来能力。
2. **能力清单口径**：这份清单是定位承诺，不是愿望清单。候选口径先过对账——每项能力服务于锚点、与调研认定的空白对得上、与已拍板的范围决策（若有）对得上，对不上账的口径不进选项。**这一步是本 skill 的事故高发区：拿参照或竞品的现成能力清单当自己的承诺，混入本项目范围外或上游未认定的事项。**
3. **设计原则**：有参照则问继承几条、是否增补本项目独有条目（增补须是本项目独有的自我定义，不是同义改写）；无参照则从空白与锚点自造。条数克制（7~10 条），多到记不住就是没提炼。
4. **文件名与命名法**：仅当参照进入且形态对齐是明确目标时才问（镜像参照命名法 vs 链内描述名）；否则按项目惯例走，不设此问。
5. **愿景长期目标**：给 2~3 个候选锚点，过**锚需求不锚概念**检验——锚在不会变的需求（合规、成本、数据主权、技术栈存量、生态完整性）上，不锚在可能被稀释、被改名的概念上；已被调研否掉的锚不复活。

完成判据：五点全部有明确答案。

## 第 3 步 · 成文

按 [doc-structure.md](references/doc-structure.md) 的骨架成文。三条写作纪律：

- **产品口径**：定位文书以产品口径写作。过程型、学习型元语境（复盘、工具链、课程）留在 README / 词汇表 / ADR，不进正文。
- **直面先行者**：调研认定了先行者，就如实写与它的关系（同类不同位、参照与复刻、错位）——不掩饰自己的起点，也不冒领品类已验证的设计首创。
- **短而密**：约百行级。定位篇不含需求清单、不含模块划分、不含实施节奏——发现这些内容混进来就是越界，删。

## 第 4 步 · 对账自检

写完逐项过，任何一项不过就改文，不带病交付：

- **词汇纪律**：有词汇表就逐条对——自称用词、禁用词零命中；没有就检查全文用词与概念辨析节一致。
- **上游一致**：与第一篇调研的数字与结论无矛盾；正文引用的数字必须是调研已拍板过的，不新增未溯源数据。
- **锚点复核**：定位一句话、愿景、设计原则逐个重过锚需求不锚概念检验——成文过程最容易悄悄滑回概念锚。
- **分工边界**：README 承担的内容（上手、营销）不在定位篇重复；链内后三篇的内容（需求、模块、节奏）不在定位篇预支。
- **口径复核**：无元语境泄漏；与先行者的关系表述到位（不回避也不谄媚）。

完成判据：五项全过。

## 第 5 步 · 沉淀

- 成文中自造的词：仓库有词汇表惯例就按惯例沉淀；没有就建议建一个——定位篇正是词汇表的天然起点。
- 口径决策若同时满足三条——难逆、无上下文会困惑、真实取舍——记一条 ADR；差任何一条就不记。
- 成文或对账中发现与调研结论或既有决策冲突：停下来报告用户，既不擅自改上游也不硬写。
