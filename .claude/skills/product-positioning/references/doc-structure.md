# 定位文书骨架（立项期）

立项期定位文书的章级骨架，提炼自先行者立项文书的公共形态：定性好、愿景立锚、论证诚实、词汇立宪、能力特性分列、路线克制、原则成宪、信息收尾。每节括号内是成文判据，写完一节对一次。目标密度：约百行级，短而密——密度明显超标，通常是需求或技术内容越界混入。

```md
# {项目名}：{一句话品类定性}（{概念别名}）

## 定位
一句话定性，可再跟一行展开。展开用对仗句式模板件（"一个 X 定义一个 Y，
一个底座运行一群 Z，私有部署，数据不出域"这类）。
（判据：读者 10 秒能向别人复述这个项目是什么。）

## 愿景
长期图景 → 定位展开段（技术栈、协议、能力面、类比金句收尾）→ 生态位论证 → 锚点宣言。
（判据：长期目标过锚需求不锚概念检验，锚在不会变的需求上；类比金句能当全文引语；
锚点宣言明说"不锚什么"。）

## 为什么需要 {项目名}
外层论证（需求真实，但卡在哪一层）→ 生态 / 技术栈位置（调研认定了先行者，
就写明谁在这个位置、还缺什么、与它的关系和接缝成本）→ 内层判断（一句话，
注明是品类共识、本项目不宣称首创，选择站在它上面）。
（判据：外层论证用当下诚实版；每个数字有第一篇调研的上游来源，不新增。）

## {核心概念}辨析
相邻概念逐层分清（各自管什么一句话说清），用一个类比收束成金句，最后一句
点明本项目是哪一层。
（判据：全项目词汇的上游在此立定；正文其余部分用词与本节严格一致。）

## 核心能力
能力逐条小节，每条一段，架构视角（对内：有什么）。
（判据：清单已过对账——每项能力服务于锚点，与已拍板的范围决策一致；
范围外或上游未认定的能力不出现，归路线图后续阶段。）

## 核心特性
卖点条目（emoji 可选），每条一句，选择视角（对外：凭什么选你）。
（判据：与核心能力不重复；安全、合规、审计类条目必须在场——这是定位的
锚点能力，不是普通特性。）

## 路线图
开发理念一段（克制、聚焦、先什么后什么）→ 分阶段清单（当前 / 规划 / 愿景）
→ 横向能力单列一组。
（判据：阶段一与核心能力口径一致；范围外的能力出现在它该在的后续阶段；
理念段能解释"为什么是这个顺序"。）

## 设计原则
有参照则继承的原则（锚层，可逐字或近逐字）在前、本项目增补在后；无参照则
从空白与锚点自造。
（判据：每条一句话可执行；增补或自造条目是本项目独有的自我定义；总数克制
（7~10 条），多到记不住就是没提炼。）

## 项目信息
四行级：语言 / 协议 / 先行者关系声明 / 文档链位置。
（判据：有参照或先行者就如实声明关系——同类、同栈或同锚点的后来者，
不掩饰、不冒领；无则写生态归属，本行可省；协议与语言与仓库实际状态一致，
立项期还没有的就写"计划采用 X"或留空，不写没有的东西。）
```

两条全文判据：

- 通读一遍：每一节要么在立定性、要么在立论证、要么在立边界——营销话术、上手指南、需求清单、模块划分出现即删。
- 用词与概念辨析节严格一致；项目有词汇表则禁用词零命中；与第一篇调研无数字矛盾。
