# 调研文档骨架（立项定位型）

章级结构，按调研对象裁剪章节，但章序体现论证顺序：先造尺子、再摆格局、后立定位。每章括号内是成文判据，写完一章对一次。

```md
# {主题}行业调研：{业界格局}、{生态位置}与{项目名}的定位

> 引言 contract：一段话给出全文路线图、"调研要回答的问题"清单、数据时点。
> （判据：读者 30 秒知道这份文档回答什么、证据是哪天的。）

## 一、什么是 {品类}

定义 → 要件清单 → 相邻概念辨析表 → 部署形态。
（判据：后文所有竞品评析和空白判断都能拿这把尺子量。）

## 二、业界格局：代表玩家与新变量

代表玩家各一段画像（规模/取向/强项/软肋/一句话定位），再写新入场变量，
最后合起来推出空白。
（判据：空白是被证据推出来的，不是断言；"市场乱"和"玩家在治理"这类
两面性事实都如实写。）

## 三、需求论证（全文重心）

大盘需求真实 → 真正的难点在哪一层 → 目标客户的铁律 → 价值锚点。
（判据：全文最硬的三到五条数据落在这一章；每条有来源。）

## 四、{技术栈/生态}的位置

现状 → 为什么这个位置值得补 → 具体支点 → 必须直面的技术债。
（判据：不回避对己方不利的事实，技术债如实入文。）

## 五、{项目名}的定位与边界

是什么 → 锚在哪（过锚需求不锚概念检验） → 与各方关系 → 边界。
（判据："不做什么"与"做什么"一样具体。）

## 六、未来方向（可裁剪）

当前边界 → 演进核心原则 → 阶段路线表。

## 附录 A：关键术语

## 附录 B：主要参考资料（按类分组）

> 数据时点与表述纪律：一手实抓的数字给时点；单一二手来源的注明来源并保守表述。
```

两条全文判据：

- 正文每个数字都能在附录 B 找到来源；正文引用过的偏门事实，附录 B 有对应条目。
- 通读一遍：每一章要么在造尺子、要么在摆证据、要么在收口定位——为凑结构而写的章删掉。
